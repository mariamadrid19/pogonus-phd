# RNA-seq analysis — Pogonus chalceus

This directory contains the scripts used for RNA-seq analysis in *Pogonus chalceus*, comparing gene expression between long-winged (LW) and short-winged (SW) ecotypes.

The workflow includes read mapping, alignment filtering, gene expression quantification, differential expression analysis, weighted gene co-expression network analysis (WGCNA), and functional enrichment analysis.

The initial processing steps were performed on the KU Leuven HPC cluster using SLURM.

## Workflow overview

| Step | Script | Description |
|------|--------|-------------|
| 01 | [01_map.sh](01_map.sh) | Map RNA-seq reads to the reference genome using HISAT2 |
| 02 | [02_filter.sh](02_filter.sh) | Filter alignments using SAMtools |
| 03 | [03_count.sh](03_count.sh) | Quantify gene expression using featureCounts |
| 04 | [04_deseq2.R](04_deseq2.R) | Identify differentially expressed genes between ecotypes |
| 05 | [05_wgcna.R](05_wgcna.R) | Identify gene co-expression modules associated with ecotype |
| 07 | [07_enrichment.R](07_enrichment.R) | Perform GO and KEGG functional enrichment analyses |

The dataset consists of 12 RNA-seq samples: six long-winged (LW) and six short-winged (SW) individuals.

## 01. Read mapping

**Script:** `01_map.sh`

Paired-end RNA-seq reads are mapped to the *P. chalceus* reference genome using HISAT2.

The script runs as a SLURM array job, processing each of the 12 samples independently.

### Procedure

1. Load paired-end FASTQ files for each sample.
2. Align reads to the reference genome using HISAT2.
3. Convert SAM output to BAM format using SAMtools.
4. Sort BAM files by genomic position.
5. Index the sorted BAM files.
6. Save alignment statistics for each sample.

### Input

- Paired-end FASTQ files (`*_R1.fq.gz`, `*_R2.fq.gz`)
- *P. chalceus* reference genome (SW assembly)
- Pre-built HISAT2 genome index

### Output

- `hisat2_bams/*.sorted.bam`
- `hisat2_bams/*.sorted.bam.bai`
- `hisat2_bams/*.hisat2.summary.txt`

The resulting BAM files contain the genomic alignments of RNA-seq reads.

### Software

- HISAT2
- SAMtools

---

## 02. Alignment filtering

**Script:** `02_filter.sh`

Mapped reads are filtered using SAMtools to retain high-quality, properly paired alignments.

### Procedure

1. Read the sorted BAM files generated in step 01.
2. Retain properly paired alignments using `-f 0x02`.
3. Retain alignments with mapping quality ≥ 30 (`-q 30`).
4. Sort the filtered alignments.
5. Index the resulting BAM files.

### Filtering parameters

| Parameter | Description |
|-----------|-------------|
| `-f 0x02` | Retain properly paired alignments |
| `-q 30` | Minimum mapping quality of 30 |
| `-b` | Output BAM format |

### Input

- `hisat2_bams/*.sorted.bam`

### Output

- `filtered_bams/*.filtered.sorted.bam`
- `filtered_bams/*.filtered.sorted.bam.bai`

These filtered alignments are used for gene expression quantification.

### Software

- SAMtools

## 03. Gene expression quantification

**Script:** `03_count.sh`

Gene-level expression counts are obtained using featureCounts from the Subread package.

The analysis uses the filtered BAM files and a BRAKER-derived gene annotation in GTF format.

### Procedure

1. Load filtered BAM files for all samples.
2. Assign aligned fragments to annotated exons.
3. Aggregate exon counts at the gene level using `gene_id`.
4. Generate a gene-by-sample count matrix.

### featureCounts parameters

| Parameter | Description |
|-----------|-------------|
| `-p` | Specify paired-end data |
| `--countReadPairs` | Count fragments rather than individual reads |
| `-B` | Require both ends to be aligned |
| `-C` | Exclude chimeric fragments |
| `-t exon` | Count reads overlapping annotated exons |
| `-g gene_id` | Summarize counts at the gene level |

### Input

- `filtered_bams/*.filtered.sorted.bam`
- BRAKER gene annotation (`.gtf`)

### Output

- `gene_counts.txt`
- `gene_counts.txt.summary`

The count matrix contains raw gene expression counts for each sample and is used as input for DESeq2.

### Software

- Subread / featureCounts

## 04. Differential gene expression analysis

**Script:** `04_deseq2.R`

Differential gene expression between the long-winged (LW) and short-winged (SW) ecotypes is analyzed using DESeq2.

The objective is to identify genes whose expression differs significantly between ecotypes.

### Procedure

**1. Data preparation**

- Import the gene count matrix generated by featureCounts.
- Import sample metadata containing sample identifiers and ecotype information.
- Match count matrix columns to sample metadata.
- Define LW as the reference condition.

**2. Gene filtering**

Genes with fewer than 10 total counts across all samples are removed.

**3. Differential expression analysis**

A negative binomial generalized linear model is fitted using:

`design = ~ condition`

The comparison is:

`SW vs LW`

Positive log2 fold changes indicate higher expression in SW individuals, whereas negative values indicate higher expression in LW individuals.

Log2 fold changes are subsequently shrunk using `apeglm`.

**4. Identification of differentially expressed genes**

Genes with an adjusted p-value (`padj`) < 0.1 are considered significant for downstream visualization.

**5. Data transformation and visualization**

Variance-stabilizing transformation (VST) is applied to expression counts for visualization and downstream analyses.

The script generates:

- Principal component analysis (PCA)
- MA plot
- Volcano plot
- Heatmap of the 50 most significant genes
- Heatmap of the 100 most variable significant genes

**6. Gene annotation**

Differential expression results are combined with BRAKER gene annotations to facilitate biological interpretation.

### Input

- `gene_counts.txt`
- `samples.tsv`
- `braker.minimal.annotation_map.tsv`

### Output

- `deseq2/DESeq2_SW_vs_LW.tsv`
- `deseq2/normalized_counts.tsv`
- `deseq2/vst_counts.tsv`
- `DESeq2_SW_vs_LW.annotated.tsv`
- `deseq2/PCA.pdf`
- `deseq2/MAplot.pdf`
- `deseq2/plots/volcano_SW_vs_LW.pdf`
- `deseq2/plots/heatmap_top50_sig_genes_SW_vs_LW.pdf`
- `deseq2/plots/heatmap_top100_variable_sig_genes_SW_vs_LW.pdf`

### R packages

- DESeq2
- apeglm
- ggplot2
- pheatmap

## 05. Weighted gene co-expression network analysis (WGCNA)

**Script:** `05_wgcna.R`

Weighted gene co-expression network analysis (WGCNA) is used to identify groups of genes with correlated expression patterns and investigate their associations with wing ecotype.

Unlike differential expression analysis, which evaluates genes individually, WGCNA identifies modules of genes exhibiting similar expression patterns across samples.

### Procedure

**1. Data preparation**

Variance-stabilized expression values generated by DESeq2 are used as input.

The expression matrix is transposed so that rows correspond to samples and columns correspond to genes.

**2. Gene filtering**

The 5,000 genes with the highest expression variance are retained for network construction.

**3. Sample clustering**

Hierarchical clustering is performed to evaluate similarities between samples and identify potential outliers.

**4. Soft-threshold selection**

Candidate soft-thresholding powers are evaluated to identify an appropriate network power.

The script selects the lowest power achieving a signed scale-free topology fit of R² ≥ 0.8.

If no candidate meets this criterion, a power of 6 is used.

**5. Network construction**

A signed weighted gene co-expression network is constructed using `blockwiseModules()`.

Main parameters:

| Parameter | Value |
|-----------|-------|
| Network type | Signed |
| TOM type | Signed |
| Minimum module size | 30 genes |
| Module merge cut height | 0.25 |
| Soft-threshold power | Automatically selected |

Genes are assigned to co-expression modules represented by colors.

**6. Module-trait relationships**

Module eigengenes are correlated with wing ecotype.

Ecotype is encoded as:

- LW = 0
- SW = 1

Positive correlations indicate modules associated with SW individuals, while negative correlations indicate modules associated with LW individuals.

**7. Gene-module membership**

For each gene, the analysis calculates:

- Module membership (kME): correlation between gene expression and module eigengene.
- Gene significance (GS): correlation between gene expression and ecotype.
- Statistical significance of gene-trait associations.

Gene annotations are incorporated into the resulting tables.

### Input

- `deseq2/vst_counts.tsv`
- `samples.tsv`
- `braker.minimal.annotation_map.tsv`

### Output

- `wgcna/genes_used_for_wgcna.tsv`
- `wgcna/chosen_soft_power.txt`
- `wgcna/module_trait_relationships.tsv`
- `wgcna/gene_module_membership.tsv`
- `wgcna/module_gene_lists/`
- `wgcna/01_sample_clustering.pdf`
- `wgcna/02_soft_threshold.pdf`
- `wgcna/03_gene_dendrogram_modules.pdf`
- `wgcna/04_module_trait_heatmap.pdf`
- `wgcna/05_top_module_eigengenes_heatmap.pdf`
- `wgcna/summary.txt`

Additional plots show module eigengene expression across ecotypes.

### R packages

- WGCNA
- data.table
- ggplot2
- pheatmap

## 07. Functional enrichment analysis

**Script:** `07_enrichment.R`

Functional enrichment analyses are performed to investigate the biological functions associated with genes identified in the inversion-related expression analysis.

The analysis uses Gene Ontology (GO) annotations and KEGG pathways obtained from eggNOG-mapper.

Enrichment is performed separately for each chromosome and direction of differential expression.

### Procedure

**1. Functional annotation**

GO terms and KEGG pathways are extracted from eggNOG-mapper annotations.

Gene identifiers are standardized by removing transcript suffixes.

**2. Gene selection**

The analysis combines:

- DESeq2 differential expression results
- A separately generated table of inversion-associated genes
- BRAKER gene coordinates

Genes with missing adjusted p-values are excluded.

**3. Gene grouping**

Genes are grouped according to:

- Chromosome
- Direction of differential expression

Expression direction is defined as:

- `SW_up`: positive log2 fold change
- `LW_up`: negative log2 fold change

**4. Background gene selection**

For each chromosome, the background consists of genes included in the DESeq2 results and assigned to that chromosome.

This chromosome-specific background is used to test for functional over-representation.

**5. Enrichment analysis**

GO and KEGG enrichment analyses are performed using `clusterProfiler::enricher()`.

Enrichment is only performed for gene sets containing at least 10 genes.

Multiple testing correction is performed using the Benjamini-Hochberg method.

**6. Identification of enriched functions**

Significant enrichment results are identified using:

`adjusted p-value < 0.05`

Results are summarized separately for each chromosome, expression direction, and annotation type.

### Input

- `braker_longest_isoforms.emapper.annotations`
- `DESeq2_SW_vs_LW.tsv`
- `inversion_genes_ranked_total.tsv`
- `braker.gtf`

### Output

- `inversion_enrichment_results/gene_counts_per_chr_direction.tsv`
- `inversion_enrichment_results/all_enrichment_results.tsv`
- `inversion_enrichment_results/significant_enrichment_results_FDR005.tsv`
- `inversion_enrichment_results/top10_terms_per_test.tsv`

Individual enrichment result tables are also generated for each chromosome and expression direction.

### R packages

- tidyverse
- clusterProfiler

## Notes on reproducibility

The scripts contain paths specific to the KU Leuven HPC environment and should be adapted before running on another system.

The mapping and filtering steps use SLURM array jobs, while gene quantification is performed as a single SLURM job.

The R analyses require the corresponding input files and sample metadata to be available in the expected working directories.

Some additional considerations:

- The HISAT2 index must be generated before running step 01.
- The `deseq2/` output directory must exist before running step 04.
- Step 05 uses `ggplot2` and `pheatmap`, which should be explicitly loaded when running the script independently.
- Step 07 requires an inversion-associated gene table generated outside the scripts included in this directory.
- The GTF gene identifiers used in step 07 should be checked to ensure they match the DESeq2 identifiers.
- The current enrichment script groups zero log2 fold changes with `LW_up`; these genes should be excluded if strictly directional gene sets are required.
